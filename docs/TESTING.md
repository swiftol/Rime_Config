# 测试与发布验证

本项目不把“配置能够编译”视为完整验收。每次正式发布至少覆盖以下层级。

## 自动检查

1. 校验 YAML、Lua、词典格式和必需文件。
2. 使用独立 Rime 引擎加载 `rime_ice_japanese` 并检查真实候选。
3. 检查安装载荷是否包含必需的 Lua 模块、运行数据和修改版前端组件。
4. 检查发布包中不存在用户数据库、个人常用语、同步数据、日志和诊断文件。

## Windows 真实输入测试

1. 在独立原生输入框中通过键盘事件输入，不依赖鼠标操作。
2. 验证中文、日语、长音、促音、浊音和中日混输。
3. 验证单行候选、展开候选、滚轮/翻页、鼠标选择和注释预览。
4. 验证 Shift、空格、Alt、Enter 等可配置按键行为。
5. 关闭并重新打开宿主应用，确认新进程加载本轮组件，而不是旧进程缓存的 DLL。
6. 冷启动时直接测试 `koqhiq → コーヒー`，不得依赖先切换到其他日语输入法。
7. 日语前缀联想必须覆盖：`sappor → 札幌` 排在首位；完整输入
   `sapporo → 札幌` 仍走精确候选；关闭联想后 `sappor` 不再出现札幌；
   “显示剩余码”开关分别验证隐藏和显示 `~o`。同时确认 `nihao → 你好`，
   且 `satpor` 不得因本功能被解释为 `sapporo`（本功能不提供 `t = っ`）。
8. Mozc 混输的连续 `n` 与中日路由必须成对回归：
   - `honnin → 本人`，不得因把 `nn` 整体吃成 `ん` 而优先得到“本院”；
   - `honninnotaichoudakenomondaidewanaku` 的前三项必须是 Mozc 日语，
     拼音硬拼出的乱码中文不得出现在候选列表；`honninno` 也必须首选
     “本人の”，且列表中不得含“红您…”；
   - `xianzaishuru → 现在输入`、`chanpin → 产品` 仍须保持中文第一；
   - `waruidesuka → 悪いですか`、`koqhiq → コーヒー` 仍须保持日语第一。
   固化脚本：`tools/self_test_mozc_mixed_routing.ps1`（只调用独立引擎，
   不操作鼠标和用户正在使用的应用）。
9. Google 云候选在干净的隔离用户目录中用独立原生测试框键盘输入
   `haoyongmzg`：本地候选立即显示，云端“好用吗这个”带云标记；
   选择它后，个人学习必须采用云返回的 `hao yong ma zhe ge`，不能
   只绑定输入时的混合简写。随后分别以 `haoyongmazhege` 和 `hymzg`
   输入，关闭云候选仍须由本地个人词库返回“好用吗这个”。等待云
   结果时不能阻塞本地候选或改变已输入编码，测后后台服务仍须运行。
   再输入 `fanfengdesp`，云端“反讽的视频”出现；重新输入
   `haoyongmzg` 和 `fanfengdesp` 时两条结果均须从本地缓存迅速返回，
   不得因另一条请求覆盖而消失。用键盘移动到第五候选后，云候选仍
   须留在第二项；服务升级后核对只有一个后台服务进程。

## 安装与升级测试

- 干净电脑首次安装；
- 从历史版本直接升级；
- 安装路径不同时的注册表与运行目录检查；
- 保留个人词频、常用语和同步数据；
- 安装后无需重启 Windows，但提示重新打开已运行的应用；
- 运行安装后验收脚本，候选管线必须返回真实候选。

完整的打包阻断项见 [`installer/RELEASE-PACKAGING-CHECKLIST.md`](../installer/RELEASE-PACKAGING-CHECKLIST.md)。
