# 设置面板部署分级

设置项必须按实际影响范围选择最轻的生效方式，不能把所有修改都交给完整部署。

## 0. 热设置：不重启服务、不重开应用

- 英文、日文注释、日语直输读音、单字候选注释开关：设置面板保存 `user.yaml`，再写入当前用户注册表的开关值与版本号。
- 外观页的候选框宽度、注释字号、候选间距、选中项留白及中/日/常用语的文字色与底色：保存 source/custom 和已有 build 缓存后，发布当前用户的外观快照。服务端将新样式附在当前窗口的刷新响应中，不重启服务。
- 已打开的 TSF 候选窗检测版本号后刷新当前候选；新会话也读取相同开关。
- 普通用户切换时不需要管理员权限。安装或升级输入法 DLL 时的注册是另一回事。

验收时在真实测试台输入编码并保持候选窗打开，修改版本号后检查同一进程、同一段未提交输入的注释切换，且后台服务 PID 不变。
外观还需运行 `TestWeaselIPC.exe /hotappearance`，检查同一 IPC 会话在修改外观版本号前后收到不同的完整样式；这个测试不抢键盘焦点。可见候选窗的尺寸和颜色仍需单独做真实窗口回归。

## 1. 仅重启服务

这些设置由 `user.yaml`、注册表或运行期 Lua/TSF 读取，不编译词库：

- Shift / Alt / 空格长按读音的运行期开关
- 日语续输锁定、日语模糊匹配各开关
- 实时句子翻译
- 常用语及纯日语自定义模糊规则 TSV

保存后只调用 `RestartServerAsync()`。

保存器必须先比较内容；值未变化时不得重写 `weasel.custom.yaml` 或方案 custom 文件，
否则仅修改运行期开关也会因为文件时间戳变化而诱发后台维护。

## 2. 轻量刷新已编译配置后重启

这些设置只改变 `build/weasel.yaml` 或已编译方案中的标量，不改变词典和拼写代数：

- 输入码是否显示在应用输入框、是否连续显示
- 展开注释是否参与宽度、是否对齐编号
- 空格三种模式、回车行为
- 生僻单字过滤门槛

流程必须是：先保存对应的 `*.custom.yaml`，再由 `BuiltConfigRefresher` 更新已有 build
缓存，最后重启服务。不得启动 `WeaselDeployer /deploy`。

## 3. 完整部署

这些设置会改变拼写代数或中文候选生成结果，必须重编译方案：

- 中文模糊纠错规则
- 自定义中文模糊匹配规则

完整部署允许大型词库耗时较长，设置工具的保护超时为 30 分钟，禁止恢复旧的 3 分钟强制终止。

## 回归要求

每次修改部署逻辑至少验证：

1. 隔离副本中把日语文字色改为黄色，`build/weasel.yaml` 立即变为 `0xFF00FFFF`。
2. 输入布局、空格/回车和生僻字门槛能直接更新 build 文件。
3. 上述轻量设置过程没有启动 `WeaselDeployer.exe`。
4. 用户实际配置在隔离测试中保持不变。
5. 中文纠错或自定义中文模糊规则仍走完整部署。
